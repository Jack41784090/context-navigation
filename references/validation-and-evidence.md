# Validation and evidence

Read before choosing checks or reporting results. Validation should establish
that each task reaches its obligations, not merely that the entrypoint is shorter.

## Preservation checks

1. Freeze the starting revision and exact working-copy baseline. Record any staged
   or unstaged changes that belong to someone else.
2. Compare each changed entrypoint against that baseline. Map every removed duty
   or explicit permission to its surviving rule, conditions and effective trigger.
   A dated receipt is not a replacement for an instruction.
3. Compare extracted bodies line by line. Record intended exceptions, including
   relative paths, heading anchors and references such as "above".
4. Resolve affected local links and explicit paths. Check headings, frontmatter,
   symlink targets and file modes, generated mirrors and inherited instructions
   separately. Verify aliases remain symlinks after editing.
5. Follow mandatory edges transitively for each representative task. Distinguish
   a navigation link from a read prerequisite. Overlapping task rows accumulate.
6. Inspect the staged tree as well as the working tree. Selective staging can
   accidentally omit a rule that exists only in another author's unstaged edits.
   Do not commit their edits to repair this. Stop and resolve the ownership or
   dependency explicitly if the owned change cannot stand alone.

## Task trace matrix

For each case record the entrypoint, matched triggers, actual documents reached,
required obligations, references intentionally skipped and observed outcome.

Include:

- A routine maintenance task that should skip unrelated creative or runtime
  manuals while retaining placement, metadata and recording duties.
- A cross-boundary proposal or review that must load every affected ownership,
  lifecycle and persistence contract before reasoning about behavior.
- A read-only discovery task that must still obey tool, privacy and authorization
  gates. Technical examples do not override current execution restrictions.
- A fresh or resumed task that activates automatic recording or session-start
  trial policies without waiting for an explicit export request.
- A dirty-tree or alias case proving unrelated edits and canonical topology survive.

Use synthetic fixtures for reusable public tests. Keep project sources, private
paths, account details, logs and evidence outside a publishable skill package.
An independent reviewer should inspect rule reachability and the final diff,
not just approve an author's summary.

## Optional paired trials

Run paired trials only with authorized tools, models and data. Verify permission
before sharing source material with each worker or provider. Freeze both
variants before testing. Give fresh, isolated workers the same task and permitted
source access, changing only the instruction variant. Record model route, effort,
harness, prompt, starting context, source revision, outputs and read logs.

Do not expose the revised skill to a baseline worker through a shared root prompt.
Do not reuse a worker's earlier answers and call the next question a fresh trial.
If inherited context or complete read logs cannot be captured, state that limit.
A source-grounded proposal is not a runtime test. A successful fixture is not
proof that a native application workflow or live integration works.

## Accounting boundaries

Report these separately:

| Quantity | What it supports | What it does not establish |
| --- | --- | --- |
| Entry-file bytes | Size of the named file at two revisions | Total reading, tokens or task quality |
| Static task read-set bytes | Sum under a stated prerequisite model | Actual agent reads or host-injected context |
| Observed reads | Documents or ranges actually recorded | Unlogged inherited context or provider token totals |
| Provider token totals | Usage reported for the specified runs | Causality without controlled comparisons |
| Task outcomes | Correctness under explicit checks | General reliability across unseen tasks |

For percentages state numerator, denominator, file encoding, unique-document or
repeated-load accounting, excluded context and whether the value is estimated.
Do not translate bytes into tokens without a stated tokenizer and complete inputs.
Do not claim minimal loading or broad acceptance from a few successful probes.

Stop when the scoped change is validated and remaining uncertainty is explicit.
If a check fails, repair and rerun it rather than lowering the acceptance claim
without explaining which obligation remains at risk.
